1. Project Overview & Design Philosophy
1.1 What Is PipPal?
PipPal is a digital trading journal for Forex, Crypto, and Stock traders that helps them log trades
manually, visualize their performance through calendar and dashboard views, and build stronger trading
discipline over time. It is built in Flutter/Dart and targets iOS and Android as a primary-mobile-first
product.
1.2 Design Philosophy
PipPal's visual language is built on two reference pillars blended intentionally:
Reference 	What We Borrow 	Emphasis
TraderSync 	Data density, metric card layout, P&L calendar

DESIGN DIRECTION The result should feel like a beautifully organised Notion workspace that has been
purpose-built to track trades. Clean, warm, structured — but with meaningful data visualisation where it counts.
1.3 Personality & Tone
The app should sit at a deliberate balance point (5 out of 10) between professional seriousness and
approachable playfulness. It is not a Bloomberg terminal (cold, dense, intimidating) and it is not a gaming
app (loud, gamified, distracting). Think: the feeling of opening a well-designed personal notebook that
takes your work seriously but does not take itself too seriously.
1.4 Core Design Principles
• Clarity first — every screen should communicate its primary purpose in under 3 seconds of
viewing
• Warm, not cold — cream/off-white backgrounds and muted colours over stark white and neon
contrasts
• Data without overwhelm — surface key metrics prominently; nest secondary data in progressive
disclosure
• Consistent rhythm — spacing, type scale, and card structure should feel unified across all screens
• Trust through typography — clean, legible numbers are the single most critical UI element in a
trading journal
• Accessible for everyone — design for beginners first; experienced traders will find depth naturally

3.4 P&L Colour Usage Rules
• Profit / Positive P&L — always use #2A9D5C (Emerald) for text, and a 10% opacity emerald tint
for card backgrounds
• Loss / Negative P&L — always use #C14953 (Crimson) for text, and a 10% opacity crimson tint
for card backgrounds
• Break-even (0.00) — use #D4854A (Amber) to distinguish from both states
• User-customisable — the profit/loss colours are overridable from Settings. The token names stay
the same; only the hex values change per user preference
• Calendar cells — profit cells: emerald fill at 25% opacity with emerald text. Loss cells: crimson
fill at 25% opacity with crimson text. No trades: cream (#E5DCC5)
COLOUR PSYCHOLOGY NOTE The warm off-white (#F5F1E8) background was chosen deliberately over pure
white. Research shows traders spend extended periods looking at screens; warm backgrounds reduce eye strain
compared to stark white. Notion adopted this same approach for identical reasons.

4.3 Typography Rules
• NEVER use bold below bodySmall (13px) — it becomes illegible on small mobile displays
• All numeric financial values (P&L, pips, percentages, RR ratios) must use tabular figure rendering
• Headings use Charcoal (#2D2D2A); secondary labels use Warm Gray (#4C4C47); meta text uses
Slate (#848FA5)
• Line heights must be set explicitly — never rely on defaults for financial data tables
• Maximum line length in descriptive text: 60 characters (roughly 300px at 14px) — prevents
overly long text lines
• Number alignment in tables and metric rows: always right-align or centre-align; never left-align

5. Spacing & Layout System
5.1 Base Spacing Unit
All spacing values are multiples of 4px. This ensures consistent rhythm across all screen sizes and aligns
with Flutter's Material 3 spacing conventions.

5.2 Screen Layout Rules
• Horizontal screen padding: 16px (spacing16) on both sides — applies to all content areas
• Safe area: Respect iOS safe areas (notch top, home indicator bottom). Bottom nav must sit above
home indicator
• Card border radius: 12px (cards), 8px (chips/tags), 16px (bottom sheet), 24px (modal dialogs)
• Card border: 1px solid #E0D9C5 (Warm Border) — no drop shadows in light mode; shadow only
in modals/bottom sheets
• Card shadow (modals/bottom sheets only): 0px 4px 24px rgba(0,0,0,0.08) — very soft,
warm-tinted
• Minimum touch target size: 44×44pt (iOS HIG), 48×48dp (Material) — whichever is larger
• Bottom navigation bar height: 56dp + safe area inset
• Top app bar height: 56dp + safe area inset (status bar)

5.3 Grid System
• Dashboard uses a 2-column card grid for metric summary cards (each card = 50% width minus
gap)
• Card gutter: 12px between all cards in grid
• Calendar uses a 7-column grid (days of week), equal column widths
• Trade log uses a full-width single column with internal table structure

dollars. EUR/USD trade, July 14'

• Do not rely solely on colour to convey information — always pair colour with an icon or text label

• Form error messages must be announced by screen readers immediately on validation (not just
shown visually)
